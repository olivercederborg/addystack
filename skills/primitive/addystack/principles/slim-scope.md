# Slim scope

**Apply when** you're shaping a plan, a stack, a review round, or a `Next` list, or
deferring a change.

Recommend the smallest option that meets the agreed goal, and build its right shape now.
It waits only when someone else owns it, it can't be built yet (no API, dependency, or
design), it dismisses an approval for an unasked change, or the user set the boundary.
Then it's a one-line follow-up, unbuilt in this run: no separate or stacked PR unless
asked. A draft, no users, or no approvals make now the cheapest time.

**Why:** "its getting way too out of hand. lets keep it simple" · "but isnt it the best
long term solution ?".

**Pattern:**
- **PRs**: vertical slices of up to about 1000 changed lines.
- **Review loops**: stop at the skill's round cap and list what's still open.
- **Option `a`**: inside the PR's scope, or it names the scope change it makes.

**Tell:** a plan that grew without the user asking.
